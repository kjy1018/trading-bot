Render.com Background Worker 배포 가이드

1) 배포 진입점
- Start Command: python -u scheduler.py
- (권장) Environment: PYTHONUNBUFFERED=1  ← Render 로그 실시간 출력

2) 빌드 명령
- Build Command: pip install -r requirements.txt

3) 의존성 파일
- requirements.txt 사용 (현재 프로젝트 기준):
  - requests
  - pandas
  - streamlit
  - streamlit-autorefresh
  - websocket-client
  - discord.py

4) 권장 설정
- Service Type: Background Worker
- Runtime: Python
- 루트 경로: 저장소 루트 (scheduler.py가 있는 위치)

5) 환경 변수(대시보드에 등록)
- APP_KEY
- APP_SECRET
- ACCOUNT_NO
- ACCOUNT_PROD_CODE
- DISCORD_BOT_TOKEN
- DISCORD_CHANNEL_ID
- (선택) GEMINI_API_KEY

6) 보유 슬롯(positions) 저장
- 기본: 프로세스 메모리 (Render ephemeral FS 에 파일 쓰지 않음)
- account.py 잔고 조회 시 KIS holdings → 메모리 스토어 즉시 동기화
- 재부팅 후에도 유지하려면 Render Disk 마운트 후:
  POSITIONS_PERSIST_PATH=/var/data/positions_state.json
- Streamlit 대시보드는 st.session_state.runtime_* 로 스케줄러 메모리를 미러링
  (같은 프로세스에서 python -m streamlit run main.py 실행 시)

7) Redis 등 외부 DB (선택)
- Worker 와 Streamlit 을 분리 배포할 때는 Redis/Postgres 등에
  positions 스냅샷을 publish 하는 방식으로 확장 가능 (현재 미구현)
